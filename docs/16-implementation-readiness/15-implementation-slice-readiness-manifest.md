# Implementation Readiness — Slice Readiness Manifest

**Status:** proposed gate baseline; post-D2 operational state reconciled by `18-d2-track-b-acceptance-propagation.md`

## Purpose

This manifest materializes the per-slice fields required by `02-authority-and-component-traceability.md`. A schema without concrete records is not readiness evidence.

No row authorizes implementation. `candidate_state_after_gate_acceptance` describes what a later explicit implementation authorization may consider if this exact readiness gate is accepted.

## Shared authority references

All slices inherit, where applicable:

- Product: `docs/01-product/product-scope.md`, `docs/01-product/capabilities.md`, accepted exclusions;
- Requirements: `docs/02-requirements/functional-requirements.md`, `business-rules.md`, `invariants.md`, `acceptance-criteria.md`;
- Security/Quality: `docs/04-quality/*`, `docs/05-security/*`;
- Architecture/System/Data: `docs/06-architecture/*`, `docs/07-system-design/*`, `docs/08-data/*`;
- API/Event: exact Phase 09/10 contracts selected by the slice;
- Reliability/Observability/Runtime/Release/Operations: exact Phase 11–15 profile joins;
- Review/Assurance: repository assurance governance and this readiness package.

`NO_PRODUCT_SURFACE` means a pure platform/governance substrate with no customer-facing capability of its own. It is not permission to create an unreviewed endpoint.

## C2 decision envelope

`eligible_for_implementation_authorization` does not mean every C2 product is preselected. A later explicit authorization may include bounded evidence-generating work for named C2 decisions, but:

1. the candidate mechanism is not canonical merely because code exists;
2. the decision record names alternatives/evidence/conformance target;
3. privileged/production authority is unavailable to the spike unless separately required and accepted;
4. canonical dependency on the mechanism begins only after reviewed selection;
5. mechanism replacement must pass the same exact logical contracts.

For `impl.customer-telemetry@1`, the D2 Track B profile is already selected/conformed. That specific decision is no longer an unresolved C2 prerequisite for the first Monitoring vertical. Other C2 dependencies used by the slice remain separately governed and may not be inferred from D2.

## Product / deferred branches

A slice row does not enable all branches inside that slice. Product-gated and C5 branches remain absent/unreachable until their own accepted authority changes state. Code presence, feature flags, route registration, deployment or tests cannot convert an upstream OPEN into enabled or `NO_APPLICABLE_CASE`.

The accepted Monitoring/Zabbix subprofile in `impl.provider-integration@1` does not authorize unrelated providers, provider write-back, Alerting/ITSM mutation or any Product-gated integration behavior.
